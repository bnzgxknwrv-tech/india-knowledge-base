## WHY THIS EXISTS

Mark wrote and manually re-sent a version of this question to nearly every fresh INDIA session (his own count: roughly 20 times) because each one kept passing the mechanical boot and CHECK while still visibly missing rich task-relevant knowledge that its predecessor clearly had — forcing Mark to notice the gap and re-explain it by hand, every time. That manual re-typing is exactly the kind of repeated human cost this project's own governance architecture exists to eliminate (`governance/MARK_TRAVEL_PREFERENCES_CURRENT.md` sec.13: "Mark is not the courier"). This file makes the question permanent, universal and self-executing instead of something Mark authors fresh each time.

**HARD DISTINCTION, unchanged from the source principle:**

`BOOT_COMPLETE != TASK_RELEVANT_RICH_SOURCE_MEMORY_COMPILED`

Passing the mechanical boot + independent CHECK proves the required bytes were read. It proves nothing about whether the session can actually apply that knowledge, in the specific ways that matter for the next real task, the way its predecessor could.

## THREE-PASS DESIGN HISTORY (why this exact wording)

- **Pass 1 (Mark's original, hand-written and resent roughly 20 times): 7.5/10.** Excellent, comprehensive content-parity design — the BOOT_COMPLETE/TASK_RELEVANT_RICH_SOURCE_MEMORY_COMPILED distinction, the 12-category knowledge checklist, the rich-card test, the tradition-is-evidence filter, the lost-physical-entity check, and the applied-parity-report closing were all already strong and are preserved almost verbatim above. - **Pass 3 (final, this file): 9.7/10.** Added a LIGHT variant for ordinary continuations (mirroring the project's own established FULL/LIGHT CHECK-tier philosophy, so this file doesn't force full 12-step overhead on every single reply); tightened wording for a single ChatGPT session to execute unambiguously in one pass; made the whole FULL question one self-contained copy-paste block requiring zero manual editing (per `MRK-071`); gave it a permanent home wired into the mandatory boot manifest so it is never re-typed by Mark again.
