# MARK DAY-BLOCK-ONLY PDF / ITINERARY RULE

Date: 2026-09-13
Status: **BINDING MARK-FACING PRESENTATION RULE**
Branch: `agent/india8-cluster-casting`

## Trigger

Mark found the existing PDF difficult to use because meaningful information about one day was spread over provenance cards, front matter, clock appendices and other sections. He does not want to assemble the day mentally from scattered parts.

## Binding future format

Every future Mark-facing itinerary/PDF must be organized **DAY BY DAY, AS SELF-CONTAINED DAY BLOCKS**.

For each physical calendar day, that day's block must contain ALL information Mark needs to understand and execute that day, including where applicable:

- exact date and weekday;
- start location / sleep base / end location;
- train / flight / car / walking legs and realistic whole-human travel times;
- station/airport names and codes;
- practical buffers and safety margins;
- every planned location in execution order;
- stable location ID and current Mark grade;
- the complete meaningful `WHY`: person, event, historical/spiritual link and exact room/tree/cave/ghat/shrine/sub-place where relevant;
- what Mark can actually do there: meditate, sit, darshan, walk, puja, eat, rest, photograph, etc.;
- desired dwell/presence time;
- opening/access/appointment/programme gates;
- predecessor -> location -> successor travel burden;
- `TOTALE TIJD VOOR DEZE LOCATIE` and `TIJD VRIJGEMAAKT ALS DEZE GESKIPT WORDT` once geometry is decision-grade;
- meals, rest and humane slack;
- B/A* optional bycatch or reserve options relevant to that exact day;
- C/rejected items only where useful to show that they were consciously excluded from that day;
- live-recheck items and material uncertainty;
- hotel/check-in/baggage logistics only to the extent they affect the actual day.

## No split information

Substantive itinerary information may NOT be parked in separate front/back sections that Mark must cross-reference.

Specifically prohibited as the only home for decision-critical content:
- separate provenance appendix;
- separate clock-plan appendix;
- separate travel-time appendix;
- separate access-warning appendix;
- separate `why this matters` appendix;
- front matter containing day-specific rules that are absent from the day itself.

A minimal cover, title, legend or one-page mechanical trip summary is allowed only if it duplicates nothing required for day execution and introduces no hidden day-specific truth.

## One source of human truth

If a fact matters on 22 December, it must appear in the 22 December block.
If a place is optional on 14 January, that optionality and reason must appear in the 14 January block.
If a train is the safety-critical backbone of 19 December, its station/time/buffer must appear inside 19 December.

The reader must be able to print or view ONE day's block and have all meaningful information for that day without searching elsewhere in the PDF.

## Completeness rule

`REPOSITORY_CAN_HAVE_MANY_SOURCE_FILES` but `MARK_FACING_PDF_HAS_ONE_DAY_ONE_COMPLETE_BLOCK`.

Internal evidence/provenance can remain in the repository for auditability. The PDF must synthesize it into the day rather than forcing Mark to inspect the archive.
