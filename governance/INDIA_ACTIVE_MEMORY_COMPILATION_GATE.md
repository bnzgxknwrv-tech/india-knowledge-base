# INDIA ACTIVE MEMORY COMPILATION GATE — READ IS NOT ENOUGH

Status: **HARD / PRE-CONTENT / ALL SUCCESSORS / ACTIVE WORKING MEMORY**
Effective: 2026-09-02
Branch: `agent/india8-cluster-casting`

## WHY THIS EXISTS
Repeated failure has occurred even after strong boot/read proof: a successor can mechanically prove that it read all mandatory files and still behave as if key rules were absent.

Failure class: **READ-WITHOUT-COMPILATION**.
- files were read;
- individual facts/rules were available somewhere in context;
- but the session did not build one reconciled working model before acting;
- stale frontier prose could overpower newer truth;
- a presentation rule could be known but not applied;
- a prior Mark grade could be available but re-presented as OPEN;
- research completeness could be mistaken for Mark triage completeness;
- bundle labels could accidentally reuse A/B/C letters reserved for grades.

Therefore `I READ EVERYTHING` is never sufficient evidence of readiness.

## 1. MANDATORY POST-READ COMPILATION
After all manifest reads and before substantive travel work, every INDIA successor must compile one internal working set from the mandatory sources.

Resolve at least these seven domains:
1. **AUTHORITY** — newest explicit Mark truth > current central decisions/state > current durable standards > frozen CCI > legacy provenance.
2. **CURRENT FRONTIER** — exact current project gate and exact first substantive action.
3. **AL BESLIST?** — current grades/locks/C/do-not-represent truth for every item likely to appear next.
4. **HUMAN DECISION FORMAT** — WHAT / WHY / current status / real-base geometry / nearest retained A+/A / natural previous-next stop / JE BENT ER TOCH / whole burden / displacement / time window / confidence / INDIA recommendation.
5. **GRADE SEMANTICS** — A+/A/A*/B/C are subjective Mark grades ONLY; never use these letters as corridor/package/scenario labels.
6. **SOURCE-LAYER SCOPE** — apply the exact current source-layer definition rather than substituting a familiar adjacent layer.
7. **DURABLE WRITE / CONTINUATION** — checkpoint each completed finding/reconciliation/Mark decision immediately, then continue automatically until a real Mark-only choice or hard external blocker.

If the session cannot state these coherently from the current repository, it is NOT ready for content even if every byte-read attestation passes.

## 2. MANDATORY CONTRADICTION PASS
Before acting, compare at minimum:
- `governance/CURRENT_STATE.md`;
- `governance/SUCCESSOR_SAFE_STATE.md`;
- `governance/CURRENT_DECISIONS_MASTER.md`;
- `governance/INDIA_CURRENT_KNOWLEDGE_MAP.md`;
- `governance/BOOT_MANIFEST_V8.json` active-cluster declaration;
- the current manifest active-cluster package;
- relevant newer explicit Mark decision/correction files;
- frozen CCI frontier prose only after filtering it against newer central truth.

If they disagree:
- do not silently select the oldest or most convenient statement;
- use authority + chronology + explicit Mark corrections to determine which controls;
- state the conflict when it affects user-facing work;
- repair durable routing before relying on the stale statement again.

If the conflict cannot be resolved from current authority, content is blocked on that exact authority conflict.

A mechanically complete boot over mutually contradictory current sources is a **FAILURE TO COMPILE**, not a valid excuse for wrong advice.

## 3. CURRENT FRONTIER / PROCESS — POINTER ONLY
This evergreen gate deliberately does **not** restate the current route frontier, affected clusters, day count, Delhi window, hotel assumption or any other mutable project state.

Current truth lives in:
- `governance/CURRENT_STATE.md` — frontier cockpit and exact next action;
- `governance/SUCCESSOR_SAFE_STATE.md` — crash-safe continuation;
- `governance/CURRENT_DECISIONS_MASTER.md` — current decision materialization;
- the manifest-selected active-cluster package;
- exact current decision/correction files routed from those sources.

Never copy frontier-specific truth into this gate merely to make it convenient. That would create another state owner and recreate the drift class this file exists to prevent.

## 4. PRESENTATION VETO — LETTERS RESERVED FOR GRADES
Never label corridors, packages, scenarios, bundles, menus or choice groups with `A`, `B`, `C`, `D`, `E`, etc.
Reason: `A+ / A / A* / B / C` already have fixed Mark-grade semantics.

Use neutral descriptive headings and ordinary numbers (`1`, `2`, `3`...) for selectable groups.

When an existing grade is displayed, make clear from context that it is a carried-forward Mark decision where that matters. Never make a prior `[B]` look like INDIA just assigned it.

## 5. DECISION-SURFACE VETO
Before asking Mark to grade an unfamiliar or burden-sensitive place, he must be able to decide without knowing Indian geography or opening another map.

Required compact card where applicable:
- `WAT IS HET / WAT DOE OF ZIE IK?`
- `WAAROM STAAT DIT IN DEZE SOURCE-LAAG?`
- `HUIDIGE STATUS: [OPEN] / explicit Mark grade / lock`
- `VANAF ECHTE SLAAPBASIS` or clearly labeled transparent proxy when a base is genuinely not selected yet
- `VANAF DICHTSTBIJZIJNDE VASTE A+/A WAAR MARK TOCH AL KOMT`
- `VANAF NATUURLIJKE VORIGE/VOLGENDE STOP`
- `LOPEN: km/min` when realistic
- `JE BENT ER TOCH: netto extra km/min` and what becomes cheap together
- `TOTALE MENSELIJKE BELASTING`, not visit time only
- `AANBEVOLEN DWELL + WAAROM`
- `WAT VERDRINGT DIT?`
- `TIJDVENSTER / SEIZOEN / TOEGANG` when decision-relevant
- `ZEKERHEID / later live recheck`
- `INDIA-ADVIES`, without assigning Mark's subjective grade.

A famous item may lose practical appeal through burden. A merely pleasant item may become much more attractive if it is nearly free beside a retained place. Geography and marginal burden are part of the decision surface.

## 6. SOURCE-LAYER SCOPE VETO
When Mark asks for a named research/source layer, load its current definition before filtering candidates.

Examples of failure to prevent:
- spiritual/person/TOP-X research substituted for LP/general-traveler research;
- guidebook famousness substituted for ordinary human experiences;
- small food/cinema/market/craft/oddity findings silently hidden before burden is known;
- a repair file labeled `COMPLETE_ENOUGH` treated as proof Mark has seen/graded its new findings.

For the exact current source-layer definition, use `CURRENT_STATE.md`, current knowledge-map routing and the active-cluster sources. Do not freeze a source-layer definition in this evergreen gate.

Hard general distinction:
`RESEARCH_COMPLETE_ENOUGH` never by itself proves `MARK_TRIAGE_COMPLETE`, and neither by itself proves `DURATION_CLOSED`.

## 7. PRE-ANSWER ACTIVE-MEMORY VETO
Immediately before every substantive answer, ask:
1. What is the current frontier?
2. What exact current file says so?
3. Did I compare the current state/master/map/manifest rather than trust only one?
4. Am I about to mention any item whose current Mark status I have not checked?
5. Am I using A/B/C letters for anything except grades?
6. Have I applied the full human decision surface, especially marginal burden and `JE BENT ER TOCH` where relevant?
7. Am I treating research completion as if Mark already graded the findings?
8. Did I load the correct source-layer definition rather than an adjacent one?
9. Does anything I am about to say contradict newer explicit Mark truth or a newer correction in this session/repo?
10. Have I checkpointed each material result already completed?

Any NO/UNKNOWN = stop, retrieve/reconcile/write first.

## 8. SUCCESSOR FAILURE TRIGGER
If Mark says any form of:
- `je mist veel`;
- `dit hadden we al`;
- `je hebt het niet goed gelezen`;
- `waarom weet de volgende dit weer niet?`;
- `dit is niet het afgesproken format`;
then treat it as a memory-system incident, not a local wording complaint.

Required response:
`STOP NEW CONCLUSIONS -> SEARCH CURRENT + HISTORY -> IDENTIFY MISSED RULE/FACT -> RECONCILE -> REPAIR MANDATORY ROUTING -> RECORD FAILURE MODE -> ONLY THEN RESUME`.

## 9. HONEST MECHANICAL LIMIT
Git/validators can prove file membership, bytes, hashes, commit shape and specific machine-readable consistency checks. They cannot prove that a language model will correctly apply every semantic rule to its next generated sentence.

Therefore protection is layered:
- one manifest for machine-readable membership/topic authority;
- narrow structural checks for contradictions that have parseable shapes;
- applied semantic CHECK topics for understanding/reconciliation;
- this pre-answer veto for live-generation behavior;
- incremental durable writes;
- Mark corrections treated as system incidents.

Do not invent a second readiness flag beside the canonical `CONTENT_AUTHORIZATION: GRANTED`. Strengthen what that existing signal means instead.

## 10. DESIGN PRINCIPLE
The goal is not for INDIA16 to be able to say `I read all files`.
The goal is for INDIA16 to behave as though the relevant truth is actually in working memory at the moment it matters.
