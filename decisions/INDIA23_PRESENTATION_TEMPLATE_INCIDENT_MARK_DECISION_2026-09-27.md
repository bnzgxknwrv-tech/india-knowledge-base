# MARK DECISION / INCIDENT — MANDATORY LOCATION CARD TEMPLATE CREATED AFTER REPEATED PRESENTATION FAILURE

Date: 2026-09-27
Decision authority: Mark, direct chat instruction to CCI
Status: HARD / BINDING / GOVERNANCE INCIDENT

## WHAT HAPPENED

Mark had already required, across four separate existing HARD governance files (`MARK_LOCATION_NAMING_CONTEXT_PROTOCOL.md`, `MARK_PERSON_PROVENANCE_PLACE_MEANING_RULE.md`, `MARK_FACING_PLACE_CARD_TRAVEL_VALUE_RULE_2026-09-13.md`, `MARK_DAY_BLOCK_ONLY_PDF_RULE_2026-09-13.md`, all already in `BOOT_MANIFEST_V8.json`'s `central_required`) that every Mark-facing location be presented with full recognition-rich naming, the real spiritual/person/event reason he'd want to go, the exact sub-place to seek, and travel-value context — never a bare Indian name plus a clock time.

CCI had read all four files and still built the Varanasi quarter-hour plan (markdown and visual artifact) with cards that were, in Mark's words, "ondermaats" — a name, a time, and one thin line, in several places nothing more than "geen lineage-link." The markdown also included `ontbijt` clock items, which `MARK_DAY_BLOCK_ONLY_PDF_RULE_2026-09-13.md` already forbids.

## MARK'S INSTRUCTION

Reread the whole complaint, fix the actual presentation, note this on GitHub, and build one mandatory, binding presentation template file so this stops recurring for CCI and for future successors.

## WHAT WAS DONE

1. Created `governance/MARK_FACING_LOCATION_CARD_TEMPLATE.md` — a single, copy-paste-ready template consolidating the naming protocol, person-provenance fields, travel-value fields and day-block format into one checklist per location.
2. Added it to `governance/BOOT_MANIFEST_V8.json`'s `central_required` (17 files now, was 16).
3. Added `FOUT 26` to `governance/MARK_TO_INDIA_SUCCESSOR_HUMAN_HANDOFF.md` (the repeated-failure checksum file), and a new item 25 to the `LAATSTE PRE-ANSWER TEST`.
4. Rebuilt the entire Varanasi quarter-hour plan (`runs/active/CCI_VARANASI_QUARTERHOUR_PLAN_WITH_LINEAGE_LINKS_2026-09-26.md`) and the visual artifact using the new template for every location, removing all breakfast clock items.

## WHY A NEW FILE, NOT JUST MORE TEXT IN EXISTING RULES

Four separate rule documents had already stated the requirement and were demonstrably not enough to force the behavior. A single, literal, fill-in-the-blank template that must be walked through per location — rather than four prose documents to synthesize from memory — is the concrete fix Mark asked for.

## EFFECT

- Does not change any place grade, night count, train choice or other locked decision.
- Applies going forward to every Mark-facing presentation of locations, in this session and all successors.
