## EHRLIJKHEID OVER DIEPTE (lees dit eerst)

Dit is een pilot binnen één sessie, geen volledig verzadigde landelijke sweep. Voor beide personen
zijn brede, meerdere-bronnen-zoekopdrachten gedaan (officiële ashram-organisaties, Wikipedia,
gespecialiseerde devotee-sites) en is elke hoofdclaim rechtstreeks gecontroleerd, niet alleen uit
een zoeksamenvatting overgenomen. Wat NIET is gedaan binnen deze pilot: voor elk van de ~20-25
gevonden plekken per persoon een diepe, primaire-bron-verificatie van exacte gebeurtenis + exacte
sub-locatie (dat zou een veelvoud van deze tijd kosten voor 2 personen, laat staan 11). Daarom:
**`PERSON_SWEEP_SATURATED` wordt voor GEEN van beide personen geclaimd.** Zie SATURATIE-STATUS
onderaan per persoon voor precies wat wel/niet is gedaan tegen de 6-punts-eis uit TASK.md.

## METHODE DIE GEBRUIKT IS

Per persoon: brede zoekopdrachten op naam + "ashram"/"birthplace"/"samadhi"/"temples list", gevolgd
door gerichte fetches van de meest gezaghebbende overzichtspagina's (eigen organisatie-website
waar beschikbaar). Geen regionale kandidatenlijst geraadpleegd tijdens deze fase.

# ZOEKPATRONEN — WAT WERKTE / NIET WERKTE

**Werkte goed**: de eigen-organisatie-adressenlijst (`shreeshreeanandamayeesangha.org/ashrams.html`,
`maharajji.love/Ashrams-Temples/`) leverde in één keer een landelijke lijst op — veel efficiënter
dan losse stad-voor-stad zoekopdrachten. Dit soort "officiële ashram-lijst"-pagina's bestaat voor
minstens meerdere van de overige 9 Top-11-namen (bijv. yssofindia.org/list-of-centres voor
Yogananda, al eerder gebruikt in de Kumaon-sweep) en zou als eerste zoekstap bij elke volgende
persoon moeten gelden.

**Werkte NIET goed genoeg**: puur regio-neutrale naamzoekopdrachten misten precies het soort
diep-historische, niet-institutionele host-plek dat deze hele taak had moeten oplossen (bijv. is
er voor Anandamayi Ma nog een "Bodh Ashram-achtige" verborgen gastheerplek die deze pilot NIET
vond, omdat een organisatie-adressenlijst per definitie alleen EIGEN instellingen toont, geen
plekken waar iemand als gast verbleef). Dit bevestigt: de organisatie-lijst-methode lost het
institutionele-blinde-vlek-probleem op, maar NIET het host-/gastheerprobleem uit de Kumaon-
root-cause. Een aparte, gerichte "wie ontving [persoon] als gast, waar" zoekronde blijft nodig en
is in deze pilot NIET systematisch gedaan (zie saturatie-punt 5 hierboven, NEE bij beide personen).

**Bevestiging van de hypothese**: de pilot vond wél degelijk nieuwe, missiekritische punten die
regionale sweeps gemist hadden (met name Kankhal/Haridwar voor Anandamayi Ma) — dus de
inverse persoon-centrische methode heeft aantoonbare meerwaarde. Maar de pilot toont ook dat
alleen "landelijk zoeken" niet vanzelf het exacte Bodh-Ashram-type-probleem (host-ketens) oplost
— dat blijft een aparte, verplichte stap nodig binnen zowel regionale als landelijke sweeps.

# GESCHATTE ATLASGROOTTE VOOR ALLE 11

Op basis van deze 2 personen (13-20 punten per persoon bij deze onderzoeksdiepte, ruim de helft
TIER 2): een ruwe schatting van **12-20 punten per persoon**, dus **circa 130-220 punten totaal**
voor alle 11, vóór ontdubbeling tegen bestaande regio-kandidaten en vóór identity-checks. Dit is
een ruwe extrapolatie, geen bewezen getal — sommige personen (bijv. Ramana Maharshi, die 54 jaar
Arunachala nooit verliet) zullen waarschijnlijk veel kleiner uitvallen; anderen (Vivekananda, wiens

#!/usr/bin/env python3
"""Bepaal live welke VNS-CAND-* nog verwerkt moeten worden.

Bron van waarheid: de data zelf. Geen enkel apart status-/progress-bestand
wordt vertrouwd (dat was de hoofdoorzaak van het vastlopen -- zie ROOT_CAUSE.md).

Gebruik:
    python3 next_candidate.py                 -> print status + volgende kandidaat
    python3 next_candidate.py --range 22 40    -> beperk tot een candidate-ID-bereik
    python3 next_candidate.py --json           -> machine-leesbare output
"""
import argparse
import json
import sys
from pathlib import Path

RUN_DIR = Path(__file__).resolve().parent.parent
INPUT_CANDIDATES = RUN_DIR / "INPUT" / "candidates.jsonl"
BRONS_DIR = RUN_DIR / "BRONS"


def load_ids(path):
    ids = []
    if not path.exists():
        return ids
    with open(path, encoding="utf-8") as f:
        for line in f:
            line = line.strip()
            if not line:
                continue
            try:
                rec = json.loads(line)
            except json.JSONDecodeError:
                continue
            cid = rec.get("candidate_id")
            if cid:
                ids.append(cid)
    return ids


def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--range", nargs=2, type=int, metavar=("START", "END"),
                         help="beperk tot VNS-CAND-<START> t/m VNS-CAND-<END>")
    parser.add_argument("--json", action="store_true")
    args = parser.parse_args()

    all_ids = load_ids(INPUT_CANDIDATES)
    if args.range:
        start, end = args.range
        all_ids = [c for c in all_ids
                   if start <= int(c.split("-")[-1]) <= end]

    done = set()
    for brons_file in sorted(BRONS_DIR.glob("BRONS-B*.jsonl")):
        done.update(load_ids(brons_file))

    remaining = [c for c in all_ids if c not in done]

    result = {
        "total_in_scope": len(all_ids),
        "done": sorted(done & set(all_ids)),
        "done_count": len(done & set(all_ids)),
        "remaining": remaining,
        "remaining_count": len(remaining),
        "next_candidate": remaining[0] if remaining else None,
    }

    if args.json:
        print(json.dumps(result, indent=2))
    else:
        print(f"In scope: {result['total_in_scope']}")
        print(f"Al verwerkt: {result['done_count']}")
        print(f"Nog te doen: {result['remaining_count']}")
        print(f"Volgende kandidaat: {result['next_candidate']}")
        if result["remaining"]:
            print("Resterend bereik: " + ", ".join(result["remaining"]))

    sys.exit(0 if not args.range or remaining or not all_ids else 1)


if __name__ == "__main__":
    main()
