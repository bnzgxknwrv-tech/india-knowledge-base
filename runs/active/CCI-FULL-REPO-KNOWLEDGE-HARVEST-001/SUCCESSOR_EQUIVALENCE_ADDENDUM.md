## Why this addendum exists

Mark has clarified the actual success criterion one level more strictly.

The goal is NOT merely that CCI produces a complete archive, report, manifest or historical reconstruction.

The goal is that all still-valid, decision-relevant knowledge surfaced by the harvest becomes readable through the mandatory successor boot layer, so that a future INDIA successor begins from practically the same project knowledge state as the outgoing INDIA regisseur.

## SUCCESSOR_EQUIVALENCE_REQUIREMENT

A fresh successor who receives only the canonical short start prompt and then executes the official mandatory boot must, before giving substantive India advice, be able to recover as nearly as practically possible the same relevant project memory as the outgoing regisseur.

That parity includes at minimum:

- who Mark is as a traveler and spiritual pilgrim;
- the durable project philosophy / selection model;
- current A+/A/A*/B/C decisions;
- hotel, guesthouse, ashram and sleep-base decisions;
- route, transfer, dwell, duration and pacing principles;
- WHY major choices matter to Mark, not only their labels;
- strong personal motivations and aversions that materially affect recommendations;
- physical-place / historic-continuity / parent-microcluster rules;
- evidence philosophy, including historical vs lineage/tradition confirmation;
- NOT_TO_BE_MISSED / regret-prevention logic;
- current fixed-core architecture and frontier;
- genuine OPEN Mark-only decisions;
- superseded/invalid/old material that must not be revived;
- worker-adoption state where it can affect current planning;
- time-sensitive facts that require later recheck rather than being treated as permanent truth;
- exact source routing needed when cluster-specific detail is required.

## A harvest atom is not finished merely because it exists in KNOWLEDGE_ATOMS

For every `CURRENT_CANON`, `CURRENT_PREFERENCE`, `CURRENT_LOCK`, or other still-applicable high-value atom, CCI must identify where that knowledge will be read by a successor.

Every such atom must map to at least one mandatory or conditional successor destination, such as:

- `MARK_CURRENT_CANON_MASTER.md`;
- `PROJECT_PHILOSOPHY_AND_SELECTION_MODEL.md`;
- `CURRENT_TRAVEL_EXECUTION_CANON.md`;
- `SUPERSEDED_AND_DO_NOT_REVIVE.md`;
- `OPEN_MARK_DECISIONS_ONLY.md`;
- or a clearly mandatory cluster-specific file named by `SUCCESSOR_START_HERE.md`.

If an important still-valid atom exists only in `COVERAGE_MANIFEST.csv`, `KNOWLEDGE_ATOMS.jsonl`, an old source file, a PR comment, a branch or `HARVEST_REPORT.md`, the successor-memory problem is NOT solved.

## Test the boot, not only the harvest

Before declaring the task complete, CCI must perform a **SUCCESSOR PARITY TEST**:

1. Pretend to be a fresh INDIA successor with no conversational memory.
2. Read only the proposed `SUCCESSOR_START_HERE.md` boot path plus whatever files that boot explicitly mandates for the current frontier.
3. Do NOT use the full harvest manifest or arbitrary repository search during the first parity pass.
4. Compare the knowledge recovered from that boot against the full current-applicable knowledge atom set.
5. List every material atom that the fresh successor would still be missing.
6. Repair the proposed successor layer.
7. Repeat until no material current-applicable knowledge gap remains, or explicitly report why one cannot safely be materialized.

Required report field:

`SUCCESSOR_PARITY_TEST = PASS / FAIL`

A truthful `100_PERCENT_SEMANTIC_COVERAGE = YES` is not sufficient by itself. Final completion requires both:

- repository knowledge coverage; and
- successor boot knowledge parity.
